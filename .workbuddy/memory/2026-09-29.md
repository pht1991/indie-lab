## phtbyte.com HTTPS 证书签发卡住（GitHub Pages 侧）
老板反映证书还是没好。实测诊断：
- DNS 全对：A → 185.199.108~111.153（灰云直连 GitHub）；www CNAME → pht1991.github.io；无 CAA 记录（不限制 CA）；GSC TXT 验证在位。
- 443 仍返回 GitHub 默认通配符证书 `*.github.io`（Let's Encrypt YR1，SAN 无 phtbyte.com）→ TLS 握手 SEC_E_WRONG_PRINCIPAL → GSC sitemap「无法抓取」。
- 结论：GitHub Pages 自定义域证书签发卡在 state 'new' 超 14h，与本站配置无关，是 GitHub 侧流水线慢/卡。

### 解法（二选一）
**A（推荐，分钟级）Cloudflare 代理 + Universal SSL 兜底**：
1. Cloudflare → phtbyte.com → DNS：把 4 条 A 记录 + www CNAME 的云**由灰转橙（代理开）**
2. SSL/TLS → Overview → 模式选 **Full**（非 Full(strict)；GitHub 源站证书是 *.github.io，strict 会因主机名不符失败）
3. 等几分钟 Edge Certificates 变 Active（Cloudflare 免费 Universal SSL 自动签 phtbyte.com）
4. 测 https://phtbyte.com → 通后 GSC 重新提交 sitemap。
- 注意：此方案下 GitHub 的 Enforce HTTPS 不再关键（Cloudflare 边缘已给 https）；若担心 http→https 重定向环，Cloudflare「Always Use HTTPS」开着即可，GitHub Enforce 留默认。

**B（等）保持灰云，等 GitHub 满 24h 自然签发**：若距离「最后一次 Save 自定义域」已超 24h 仍 *.github.io，属异常 → 提 GitHub Support ticket。
